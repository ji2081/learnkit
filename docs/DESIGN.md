# 설계 노트

## 출발점 — 평균의 함정

특수학급과 일반학급, 양 극단을 가르치며 알게 된 것:

> **하나의 자료가 여러 수준의 사람을 만나면, 쉽게 아무에게도 안 맞는 평균이 된다.**

처음 보는 사람에게 맞추면 아는 사람이 지루해하고, 아는 사람에게 맞추면 처음인
사람이 첫 줄에서 멈춘다. 가운데를 잡으면 양쪽 다 놓친다.

**교실만의 문제가 아니다.** README도, 온보딩 문서도, 튜토리얼도 같은 자리에 선다.
"초보자한테는 어렵고 숙련자한테는 지루한 문서"는 어느 저장소에나 있다.

그래서 자료를 여러 벌로 나누는 대신, **펼쳐지는 정도를 값으로 뺐다.**

```
Lesson   = 무엇을 다룰지  (한 번만 정의)
Learner  = 어디까지 펼칠지 (받는 쪽에 따라)
```

정의는 그대로 있고, 펼침만 달라진다.

## 펼침의 축은 어떻게 골랐나

이론에서 내려온 게 아니다. 가르치는 동안 **흥미가 꺼지는 순간**이 몇 가지로
반복된다는 걸 보고, 그 네 순간에 하나씩 대응하는 장치를 만들었다.

| 꺼지는 순간 | 대응 | 구현 |
|---|---|---|
| ① 왜 치는지 모를 때 | 한 줄씩 따라가기 | `trace.py` — `sys.settrace` |
| ② 갑자기 어려워질 때 | 난이도 다이얼 | `lesson.py` — `inspect.getsource` |
| ③ 결과가 안 보일 때 | 한 정의, 여러 화면 | `renderers.py` — `Protocol` |
| ④ 에러가 무서울 때 | 에러 튜터 | `error_tutor.py` — `sys.excepthook`, `difflib` |

## 구조

```
Lesson  ──▶  View  ──▶  Renderer
(무엇을        (그릴        (어떻게
 다룰지)       재료만)      보여줄지)
   ▲
Learner
(어디까지
 펼칠지)
```

**Lesson은 화면을 모른다.** 이게 "한 번 정의하면 어디로든"이 구호가 아니라
실제로 성립하는 조건이다. 렌더러가 Lesson 내부에 손대기 시작하면 그 순간
결합이 생기고, 새 화면을 붙일 때마다 Lesson을 고쳐야 한다.

그래서 둘 사이에 `View`라는 **얼어붙은 값**을 하나 놓았다. 렌더러가 받는 건
Lesson이 아니라 View다. 나중에 Lesson이 바뀌어도 렌더러는 안 깨진다.

`Renderer`는 추상 기반 클래스가 아니라 `typing.Protocol`이다. learnkit을
임포트하지 않아도, `name`과 `render(view, **options)`만 있으면 그것은 이미
렌더러다. 구조적 서브타이핑을 쓴 이유는 **기여 장벽을 낮추기 위해서**다.

## 난이도 다이얼

> 코드 난이도가 아니라, *생각의 깊이*로 무게를 주는 부분.

하나의 수업을 **보기 → 바꾸기 → 만들기** 세 단계로 늘려, 특수학급부터
대학·심화까지 *한 자료로* 포괄한다. (낮은 바닥 · 높은 천장)

| 단계 | 학습자가 하는 일 | 스캐폴딩 | 누구에게 |
|---|---|---|---|
| **보기** | 결과를 관찰 (코드 안 건드림) | (선택) 한 줄씩 따라가기 | 입문·특수학급 — *낮은 바닥* |
| **바꾸기** | 데이터를 자신의 것으로 수정 | `hint` 도움말 | 일반학급 — *중간* |
| **만들기** | `build` 함수를 직접 수정 | 코드 공개 + `challenge` | 심화·개발자 지망 — *높은 천장* |

'만들기' 단계에서 학습자에게 보여주는 코드는 우리가 따로 적어둔 문자열이
아니라 `inspect.getsource(self.build)`로 꺼낸 **실제로 방금 실행된 그 함수**다.
설명과 코드가 어긋날 수 없다.

천장 끝(만들기)은 바로 *개발자의 세계* → 같은 자료가 입문자도, 미래의
메이커도 키운다.

## 왜 이렇게 만들었나 — 세 가지 결정

### 1. 에러를 던지지 않고 돌려준다

```python
result, error = lesson.run(branch)
```

학습자가 `build`를 깨뜨리는 건 '실패'가 아니라 **예상된 흐름**이다.
'만들기' 단계는 애초에 코드를 고치라고 만든 단계다. 그래서 예외를 위로
던지지 않고 튜터가 설명한 딕셔너리로 바꿔서 돌려준다. 렌더러는 그걸
빨간 카드 대신 초록 카드로 그린다.

### 2. 웹앱 렌더러는 화면이 아니라 코드를 만든다

다른 두 렌더러와 성격이 다르다. `as_webapp()`은 그리는 대신
**혼자 돌아가는 streamlit 파일을 써낸다.** 학습자의 `build` 소스를 그대로
심어서, 생성된 앱은 learnkit 없이도 동작한다.

수업 자료를 파일 하나로 배포할 수 있게 하려는 의도다. 학교에서는
"이거 설치하세요"가 생각보다 큰 장벽이다.

### 3. 코어는 아무것도 없어도 동작해야 한다

rich·ipywidgets·streamlit·anthropic·pyttsx3 전부 선택이다. 하나도 없어도
콘솔 렌더와 에러 튜터는 표준 라이브러리만으로 돌아간다.

학교 컴퓨터에는 아무것도 못 깔 때가 많다. 발표 라이브 데모에서도
같은 이유로 안전하다.

## 아직 못 한 것

- **스크린리더 지원.** 다중 표현·고대비·큰 글씨까지는 했지만 ARIA 라벨과
  키보드 내비게이션은 없다. "접근성이 기본"이라고 말하기엔 아직 부족하다.
- **한 줄씩 따라가기의 한계.** `sys.settrace`로 지목한 함수 안쪽만 따라간다.
  중첩 함수와 재귀는 아직. 리스트 컴프리헨션은 파이썬 3.11 이하에서
  별도 코드 객체라 한 줄로만 보인다.
- **근거.** 이 도구가 실제로 흥미를 되살리는지는 아직 측정하지 못했다.
  지금 말할 수 있는 건 "꺼지는 지점을 봤고, 그걸 코드로 붙잡아봤다"까지다.

## 참고

'낮은 바닥, 높은 천장'은 페퍼트·레스닉의 표현이다. 교육학에는 이런 고민을 다루는
UDL(보편적 학습 설계)이라는 틀도 있는데, 나중에 찾아보고 알았다.

**우리는 교육학을 전공하지 않았다.** 이 문서는 이론 해설이 아니라 제작 노트다.
출발점은 '평균의 함정'과 '흥미가 꺼지는 순간' 네 가지 — 둘 다 현장에서 본 것이고,
그 이상은 주장하지 않는다.
